# cxt v0.5.2 — bounded reference resolution and review reliability

Versioned notes for the stable 0.5.2 release. The user authorized the main merge
and stable publication on 2026-10-16 after local candidate validation. Downloads
exist only after the tagged Release workflow publishes its assets; a version in
Cargo.toml or a successful build-only run is not publication.

## Scope

This is a focused patch to local source retrieval and reviewed-context handling,
not completion of the DeepQuery roadmap. Existing CLI/TUI/MCP and instruction-only
skill interfaces remain shared across the same core pipeline. No LLM, provider,
embedding download or network call is added to selection.

- Supported Python from-import/module aliases and JavaScript/TypeScript
  named/default/namespace imports participate in local reference resolution.
  Supported scope/shadowing rules prevent unrelated callback or object-receiver
  matches. Ambiguous and unsupported forms remain unresolved.
- Bounded weighted traversal prefers import/local-bound evidence over unique-name
  heuristics. Reasons expose call/reference direction, binding method and original
  source locations, including unresolved targets and suppressed high-fanout paths.
- Bare calls inside supported declared JS/TS classes resolve through lexical
  bindings rather than incorrectly selecting a same-named class method. Java's
  supported implicit field lookup remains separate. This is not complete
  class-expression, type or dynamic-dispatch resolution.
- Rust impl methods retain owner-qualified identities such as `IndexStore::load`;
  bare calls do not implicitly capture an impl namespace. Focused supporting
  imports exclude unrelated recognized nested scopes. Original source spans are
  preserved; focused fragments are not promised to compile independently.
- Import-only support no longer inherits almost the entire query anchor score.
  Independent lexical/symbol/graph evidence survives candidate merging.
- Ready TUI output-only settings reuse reviewed snapshots. Source-affecting and
  output-path changes still reload. Source/HEAD freshness and omitted pins remain
  export blockers. A stopped worker clears the exportable plan and reports how
  to recover rather than leaving the interface busy indefinitely.
- The TUI test wait drains queued current-revision results before declaring a
  timeout. Its ten-second deadline remains; obsolete results do not satisfy it.
  This fixes a demonstrated harness ordering error, not every timeout scenario.
- Budget refusals name `--budget` or MCP `max_tokens`, explain rendered metadata
  overhead, suggest a safe increase or narrower request, and do not export an
  empty packet as success. Output-byte refusals remain distinct.
- MCP related-test discovery retains tests reached through bounded reverse
  imports, not only filename matches. Tool discovery explains maps versus source
  bodies, packet overhead and safe follow-ups before agents make their first call.

Parser-cache schema changes invalidate older symbol metadata. No raw source bodies
are persisted. MCP retains its canonical workspace, fixed redaction, request/scan
caps and no-persistent-cache-write policy. Candidate-wide `--secrets fail` remains
deliberate: findings can block export even in a candidate later omitted by budget.

## Known limitations

- This is syntax-subset static resolution, not full type/trait/overload, macro,
  compiler or runtime-dispatch analysis. Re-exports, complex bindings and broader
  language coverage remain incomplete. Heuristic edges are not verified facts.
  Java implicit method-call helper expansion is incomplete, including a retained
  case where the requested method is exported but its bare-called helper is not.
- MCP `search` intentionally returns symbol maps. Maps are orientation, not
  implementation coverage. Use `get_symbol` or focused `get_context` for source
  bodies, inspect omissions, and narrow requests when metadata competes for budget.
  A known 2,500-token multi-file search still retains only one map.
- Persistent lexical postings, bounded MCP session-index reuse, behavioral
  READS/WRITES/events/routes, a general terminology bridge, global span optimization
  and SCIP integration are deferred. They are not prerequisites claimed complete
  by this bounded patch.
- Scan limits use cooperative elapsed time and may refuse a request under heavy
  machine load. An in-flight filesystem/parser/Git operation cannot be interrupted.
  No partial context is exported on limit failure. The historical TUI worker
  deadline failure and parallel optimized integration scan timeouts remain retained;
  the exact historical cause is not established by a successful serial replay.
- Secret detection is best effort. Synthetic retrieval checks are not independent
  public-task accuracy, downstream coding success or competitive-superiority proof.
- External agent feedback reported a whole-repository scan stall. The pasted
  transcript lacks the exact command/version and complete error, so its cause is
  unverified. Focused successes and a synthetic scale run do not close that report
  or establish a 9/10 agent rating. See the agent-usability backlog in TODO.md.

## Release disposition and verification

This release intentionally ships the bounded reference-resolution/MCP/TUI fixes,
not the full DeepQuery roadmap or an independently established 9/10 retrieval
claim. Historical load-sensitive cooperative scan refusals remain a known
fail-closed limitation. Three unchanged-deadline worker repeats passed after the
reproduced polling-order fix; that does not establish the historical root cause.
The external whole-repository stall still needs an exact sanitized reproduction.

The [candidate build-only run](https://github.com/chinmaykrishnroy/cxt/actions/runs/38864100676)
passed all six targets: Windows x64/ARM64, Linux x64/ARM64 and macOS Intel/Apple
Silicon. Final-main checks must also pass before tagging. Native tests are distinct from
cross-compilation: Windows and Linux ARM64 artifacts are cross-compiled, not
ARM runtime acceptance. Installer scripts are unchanged; local candidate checks
did not install into the user's PATH. Verify the published checksums and downloads
after the tagged workflow; package-manager submissions are separate publication
steps and must reference immutable published assets.

The historical [DEV verification](../DEV_MCP_TUI_VERIFICATION.md) and
[MCP dogfooding log](../MCP_DOGFOODING.md) retain earlier findings. They do not
substitute for final-source validation or a successful tagged release workflow.

The [2026-10-16 candidate verification](../STABLE_0_5_2_CANDIDATE_VERIFICATION.md)
records the new frozen Windows binary, 194-test gate, optimized integration
replay, actual stdio/TUI checks, synthetic results and retained limitations.
Cross-platform results, asset publication and external package-manager updates
remain separate evidence.
