# cxt 0.5.2-dev.1 — query-resolution preview

This is an **opt-in development prerelease**, not stable 0.5.2. Stable users
should stay on 0.5.1. It previews the first part of the model-free query
architecture, not the complete DeepQuery design or best-in-class retrieval.

## Changes to test

- Supported Python import/module aliases and JavaScript/TypeScript
  named/default/namespace imports with direct declaration exports.
- Shared lexical/import binding decisions for query expansion and focused
  helpers; supported shadowing cases avoid unrelated same-name definitions.
- Bounded weighted reference traversal with original call-site locations,
  call/reference direction, binding evidence and unresolved/hub diagnostics.
- Parser-cache schema invalidation, public CLI/core regressions and synthetic
  binding fixtures. No new model calls, cloud dependencies or weaker security
  policy. CLI/TUI/MCP use the same core.

## Explicit opt-in installation

Assets appear only after this tag's release workflow succeeds. Review the
downloaded installer before running it. The scripts verify asset checksums.
These commands replace your existing cxt installation; use direct assets in a
separate directory if you want to retain both binaries.

Windows PowerShell:

```powershell
$env:CXT_VERSION='v0.5.2-dev.1'
try {
  irm https://github.com/chinmaykrishnroy/cxt/releases/download/v0.5.2-dev.1/install.ps1 | iex
} finally {
  Remove-Item Env:CXT_VERSION -ErrorAction SilentlyContinue
}
cxt --version
```

macOS / Linux:

```bash
curl --proto '=https' --tlsv1.2 -LsSf https://github.com/chinmaykrishnroy/cxt/releases/download/v0.5.2-dev.1/cxt-installer.sh | CXT_VERSION=v0.5.2-dev.1 sh
cxt --version
```

Normal `releases/latest` installs and stable package-manager channels are not
changed by this prerelease. Raw Windows `.exe` downloads do not modify PATH;
macOS DMGs contain a CLI executable. Debian package metadata uses `0.5.2~dev.1`
to sort below final 0.5.2.

Try from a trusted project:

```bash
cxt --query "changing one room's volume affects every room" --context adaptive --model cl100k --budget 8000 --manifest --stdout
cxt --tui
cxt --mcp /absolute/path/to/project
```

The example is an investigation request, not a guarantee that an arbitrary
project's shared-state bug can be resolved. Bare `cxt` still copies current-folder
context to the clipboard; automated clients should choose stdout or a file.

## Known limitations and evidence

- Resolution covers a syntax subset, not compiler/type or general dynamic
  dispatch semantics. Re-export chains, wildcard imports and complex binding
  cases remain gaps. Unique-name links remain explicitly heuristic.
- No persistent lexical postings, behavioral state/event graph, general
  terminology bridge, global span optimizer or SCIP adapter is shipped here.
- MCP search may omit important explicit candidate files as dependency expansion
  and metadata compete for budget. A map is not implementation coverage.
  Narrow requests and check omissions; use focused symbol follow-ups.
- Rust impl methods may appear under unqualified identities; `IndexStore::load`
  failed in local dogfooding while `load` succeeded. Focused supporting imports
  can include unrelated scopes; focused text is not necessarily standalone code.
- A prior local full test run hit a TUI worker deadline. Isolation and subsequent
  full reruns passed; its root cause is not confirmed or declared fixed.
- Final validation also observed a TUI scan timeout and an optional Gitleaks
  timeout during concurrent checks. The same TUI request subsequently reached
  Ready in isolation; the scanner passed three isolated repeats without policy
  or deadline changes. These are retained failures, not fixed issues. TUI review
  graph preparation can cover the enclosing Git repository even when input paths
  are narrow; inspect scan-limit diagnostics and narrow the workspace as needed.
- Candidate-wide `--secrets fail` remains intentional: original findings in a
  prepared candidate can block the whole export even if budget would omit it.
  Scanner errors fail closed; secret detection remains best effort.
- Development-influencing synthetic results are not independently reviewed
  holdout results, downstream coding success or competitor-superiority evidence.
  See [verification](https://github.com/chinmaykrishnroy/cxt/blob/v0.5.2-dev.1/docs/QUERY_ARCHITECTURE_VERIFICATION.md),
  [MCP findings](https://github.com/chinmaykrishnroy/cxt/blob/v0.5.2-dev.1/docs/MCP_DOGFOODING.md)
  and [remaining work](https://github.com/chinmaykrishnroy/cxt/blob/v0.5.2-dev.1/TODO.md).

Fresh local gates, exact executable/report hashes and retained timeout/budget
failures are in [prerelease validation](https://github.com/chinmaykrishnroy/cxt/blob/v0.5.2-dev.1/docs/releases/v0.5.2-dev.1-validation.md).

Release workflow logs distinguish native-host tests from cross-compiled assets;
cross-compilation does not establish target-device runtime acceptance.

## Return to stable 0.5.1

Run the corresponding installer above with both URLs and `CXT_VERSION` changed
to `v0.5.1`. For manually installed Debian packages, explicitly install the
0.5.1 `.deb` as a downgrade, for example `sudo dpkg -i ./cxt_0.5.1_amd64.deb`
on amd64 (use the matching architecture). Reopen the terminal if PATH changed
and check `cxt --version`.

Please report the command, platform, version, omission/refusal details and a
minimal redistributable reproducer. Do not upload credentials or private source.
